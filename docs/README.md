# OctoAcme Project Management Documentation

Welcome — this is the central entry point for OctoAcme project management processes. Use these documents to understand how we start, plan, execute, release, and improve work.

## Quick overview of OctoAcme project management
- Customer-first, iterative delivery: deliver small, testable increments and iterate using data.
- Clear ownership: every project has a named Project Manager (PM) and Product Lead (PdM).
- Defined lifecycle: Initiation → Planning → Execution → Release → Retrospective & Continuous Improvement.
- Team rhythm: daily standups, weekly delivery syncs, end-of-sprint demos/reviews.
- Quality-first: automated tests, security scanning, and manual QA as needed.
- Risk-aware: maintain a simple risk register, escalate via defined paths, and communicate regularly.
- Continuous improvement: run retrospectives and convert action items into backlog work.

## How to use this README
- New team members: read the Overview, then the Initiation and Planning docs to understand how projects start.
- Delivery teams: follow the Planning and Execution docs day-to-day; use the Risk and Release guides as needed.
- Project leads: keep the project README updated with links to the one-pager, roadmap, and decision logs.
- Copilot Spaces: add process-specific docs into `.copilot/` to make them available as context.
